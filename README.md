# HidenKO

Полностью прозрачная строка меню для macOS 14–15: над строкой меню видны обои, а не системная
подложка. Проверено на macOS 15.8.1, два дисплея: MacBook с вырезом (Retina, 2×) и внешний
ультраширокий монитор (1×).

Приложение живёт только в строке меню (без иконки в Dock), не требует отключения SIP,
ничего не внедряет в другие процессы и не изменяет файлы обоев пользователя.

## Установка и запуск

Нужны Xcode Command Line Tools (`swiftc`, `actool`, `codesign`) и Mac на Apple Silicon
(сборка под `arm64`, минимальная система — macOS 14.0).

```bash
./build.sh
open build/HidenKO.app
```

`build.sh` каждый раз удаляет папку `build/` и собирает всё заново:
1. копирует `Info.plist`;
2. компилирует иконку `Icon/AppIcon.icon` через `actool` в `AppIcon.icns` (macOS 15) и `Assets.car`
   (Liquid Glass, macOS 26+);
3. собирает `Sources/*.swift` через `swiftc -O` с фреймворками AppKit и QuartzCore;
4. подписывает бандл первым найденным сертификатом «Apple Development»; если сертификата нет —
   ad-hoc подписью (`codesign --sign -`).

Подпись сертификатом важна: у ad-hoc подписи «личность» приложения меняется с каждой сборкой, и macOS
после каждой пересборки заново спрашивает доступ к папкам («Загрузки», «Документы», «Рабочий стол»),
если обои лежат там. Пока на запрос не ответили, обработка обоев стоит.

### Автозапуск
Скопируйте `HidenKO.app` в `/Applications`, затем: Системные настройки → Основные → Объекты входа →
добавить `HidenKO.app`. Если раньше в автозапуске была другая копия (например, из папки `ClearBar`),
удалите её, чтобы не работали две копии сразу.

## Если скачали готовое приложение

Приложение не нотаризовано Apple, поэтому при первом запуске macOS скажет, что не может проверить
разработчика. Чтобы открыть:

1. Перетащите `HidenKO.app` в «Программы» и попробуйте открыть. Появится предупреждение, закройте его.
2. Откройте Системные настройки → Конфиденциальность и безопасность. Внизу будет «HidenKO заблокировано»,
   нажмите «Всё равно открыть» и подтвердите паролем.

Или одной командой в Терминале:

```bash
xattr -dr com.apple.quarantine /Applications/HidenKO.app
```

## Использование

После запуска в строке меню появляется значок `menubar.rectangle`. В его меню:

| Пункт | Что делает |
|---|---|
| **Прозрачная строка меню** (галочка) | Включает и выключает эффект. При выключении на все мониторы возвращаются исходные обои. |
| **Вернуть обои и выйти** (⌘Q) | Возвращает исходные обои и завершает приложение. |

Обои по-прежнему меняются в Системных настройках → Обои: приложение само заметит новую картинку
и через секунду пересоберёт полоску.

Исходные обои также возвращаются при штатном завершении процесса сигналами `SIGTERM`, `SIGINT`,
`SIGHUP` (например, `kill <pid>` или выход из системы).

## Как это работает

Системная строка меню в macOS 14–15 сама решает, какой ей быть: светлой или тёмной, полупрозрачной
или нет. Сделать её прозрачной напрямую нельзя, поэтому HidenKO действует обходным путём, в три шага.

1. **Чёрная полоса в обоях.** Для каждого дисплея текущие обои отрисовываются так же, как их
   показывает система (масштаб «Заполнить экран», текущий светлый или тёмный вариант), в копию.
   В этой копии верхняя полоса высотой со строку меню закрашена чистым чёрным. Копия ставится
   обоями. Исходный файл не изменяется.
2. **Строка меню становится чёрной.** Над чёрным фоном системная строка меню тоже чёрная,
   а текст и значки в ней белые.
3. **Окно-наложение.** Поверх строки меню лежит прозрачное для кликов окно уровня `statusBar`.
   Внутри него:
   - `CABackdropLayer` берёт то, что находится под окном: чёрную строку меню с белым текстом;
   - сверху слой с **исходной** полосой обоев в режиме смешивания *Screen* (`screenBlendMode`).

   При смешивании *Screen* чёрный цвет становится картинкой обоев, а белый остаётся белым. В итоге
   видны обои, а поверх них белый текст и значки строки меню.

Высота полосы берётся из настоящего окна строки меню в WindowServer: 37 pt на MacBook с вырезом,
24 pt на внешнем мониторе. К ней добавляется 1 pt запаса. Если окно строки меню не найдено,
высота считается как разница `frame` и `visibleFrame` экрана.

`CABackdropLayer` — закрытый класс QuartzCore. Приложение ищет его во время работы и задаёт только
те свойства, на которые он отвечает. Будущее обновление macOS может это сломать: тогда в лог
пишется `CABackdropLayer not available`, и полоска не будет работать.

## Устройство кода

| Файл | Что внутри |
|---|---|
| `Sources/main.swift` | `AppDelegate`: меню в строке меню, подписка на системные уведомления, обработка сигналов, запуск `Engine`. |
| `Sources/Engine.swift` | `Engine`: состояние каждого дисплея, решение «пересобрать или оставить», установка и возврат обоев, слежение за изменениями. |
| `Sources/WallpaperProcessor.swift` | Тяжёлая обработка картинки, поиск высоты строки меню, служебные функции для сгенерированных файлов. |
| `Sources/OverlayWindow.swift` | Окно-наложение с `CABackdropLayer` и слоем полосы обоев. |
| `Info.plist` | `LSUIElement = true` (без Dock), идентификатор `local.hidenko.app`, минимум macOS 14.0. |
| `Icon/AppIcon.icon` | Файл Icon Composer. `Icon/source.png` — исходник картинки. |
| `build.sh` | Сборка, см. выше. |

### Engine
Монитор определяется по **UUID** (`CGDisplayCreateUUIDFromDisplayID`), а не по `CGDirectDisplayID`:
номер меняется после отключения и повторного подключения монитора, UUID остаётся прежним.

Для каждого дисплея (ключ — `CGDirectDisplayID`, пока он подключён) хранится `ScreenState`:
- `uuid` — какому физическому монитору принадлежит состояние (если тот же номер получил другой
  монитор, состояние сбрасывается);
- `original` и `originalOptions` — исходные обои пользователя и их параметры масштабирования;
- `processed` — результат обработки: полоса, путь к сгенерированному файлу, высота полосы,
  признак «обои зависят от темы»;
- `window` — окно-наложение.

Главный метод `refresh()` проходит по всем экранам и для каждого:
1. находит высоту строки меню; если строки меню нет (автоскрытие, полноэкранное приложение),
   прячет окно и идёт дальше;
2. если на экране уже стоит наш файл, высота полосы прежняя и пересборка не требуется,
   только ставит окно над строкой меню этого экрана и показывает его;
3. иначе запускает пересборку (`rebuild`).

`rebuild` сначала выясняет, какие обои исходные. Сгенерированный файл никогда не считается
исходным: его полоса уже чёрная, и окну нечего было бы показать. Порядок поиска оригинала:
1. если на экране обычный (не наш) файл — это выбор пользователя, он и становится оригиналом.
   Исключение: если монитор только что подключали (см. ниже) и у него уже есть запись, а система
   подсунула другой файл, возвращается прежний оригинал;
2. если на экране наш файл: запись (`Record`) этого монитора по UUID;
3. запись другого монитора, у которой `generated` совпадает с файлом на экране (новый или
   переподключённый монитор унаследовал чужой сгенерированный файл);
4. старый формат (путь по номеру дисплея, версия 1) — на всякий случай;
5. если ничего не найдено, дисплей не трогается, а в лог пишется сообщение.

Запись (`Record`) для каждого монитора: путь к оригиналу, параметры масштабирования и путь к
сгенерированному файлу. Хранится в `defaults read local.hidenko.app records.v2`, ключ — UUID монитора.
Поэтому оригинал находится, как бы система ни перепутала номера мониторов и файлы.

Обработка идёт в фоновой очереди `hidenko.worker` с приоритетом `utility`. Один дисплей не
обрабатывается дважды одновременно (`inFlight`). После обработки в главном потоке:
новый файл ставится обоями, окно обновляется, запись сохраняется на диск, лишние файлы
удаляются (`collectGarbage`: удаляются только файлы, на которые не ссылается ни одна запись и ни одна
строка хранилища обоев macOS, `Store/Index.plist`; файл отключённого монитора сохраняется, система
вернёт его при подключении).
Окно показывается через 0,8 с, чтобы система успела перекрасить строку меню в чёрный.

**Почему важно хранилище обоев.** macOS хранит выбор обоев в нескольких местах `Index.plist`: по
дисплеям, по рабочим столам (Spaces), «системные по умолчанию». `setDesktopImageURL` обновляет только
часть из них, а после подключения монитора или пробуждения система может взять другую запись. Если
такая запись называет уже удалённый сгенерированный файл, у экрана пропадают обои. Поэтому такие
файлы не удаляются, а если файла уже нет, `healDanglingReferences` кладёт на его место копию текущего
файла этого дисплея.

**Резервная копия оригиналов.** Кроме записей в настройках, при каждом принятии оригинала пишется
`last-known.json` (монитор → путь к оригиналу). `disable()` его не трогает. Если записи потеряны
(очищены настройки, возврат обоев не сработал), оригинал берётся оттуда.

`disable()` возвращает оригиналы на все подключённые дисплеи (по состоянию, по записи монитора или по
записи, чей `generated` стоит на экране) и **проверяет, что система их применила**. Записи удаляются
только для тех мониторов, где возврат подтверждён. Запись отключённого монитора остаётся до
следующего запуска.

### WallpaperProcessor
`process(...)` за один проход:
1. открывает исходную картинку (`NSImage`, поддерживает и динамические `.heic`);
2. рисует её в непрозрачный битмап размером с экран в пикселях, в цветовом пространстве экрана,
   масштаб «Заполнить экран», под текущей темой оформления;
3. копирует верхние строки битмапа в отдельный маленький буфер: это полоса для окна-наложения;
4. закрашивает верхнюю полосу полного битмапа чёрным и сохраняет его в PNG;
5. проверяет, сколько картинок в исходном файле: больше одной — значит, обои динамические
   и зависят от темы.

### OverlayWindow
Окно без рамки, без тени, прозрачное для кликов, на всех рабочих столах (`canJoinAllSpaces`,
`stationary`), не участвует в переключении окон и не становится активным. `update(...)` меняет полосу
без анимации.

Окно знает UUID своего монитора (`displayUUID`) и само следит за своим местом:
- `reposition()` ставит окно точно над строкой меню этого монитора; если монитор не подключён,
  прячет окно;
- `show()` показывает окно, только если оно стоит на своём месте;
- при любом сдвиге окна (`didMove`, `didChangeScreen`) вызывается `reposition()`. Так окно сразу
  возвращается, если macOS при смене мониторов или пробуждении перенесла его на другой экран;
- `constrainFrameRect` переопределён: AppKit не подвигает окно по своим правилам.

Всё это работает на событиях, без опроса.

## Когда приложение что-то делает

Приложение ничего не опрашивает в цикле. Обновление запускают события:

| Событие | Реакция |
|---|---|
| Изменились мониторы (подключение, отключение, разрешение, расположение) | открывается окно ожидания на 10 с, `refresh` через 1 с |
| Сменился рабочий стол (Space) | `refresh` через 0,5 с |
| Мак проснулся, пользователь вернулся в сеанс | как при смене мониторов: окно ожидания и `refresh` через 1 с |
| Мониторы погасли | окна прячутся, таймер останавливается, `refresh` не выполняется |
| Мониторы зажглись | таймер запускается, `refresh` через 1 с |
| Переключение светлой и тёмной темы | `refresh` через 0,5 с; пересобираются только динамические обои |
| Изменилась папка `~/Library/Application Support/com.apple.wallpaper/Store` (выбраны другие обои) | `refresh` через 0,7 с |
| Страховочный таймер | `refresh` раз в 60 с (допуск 30 с) |

Несколько событий подряд склеиваются в один `refresh`. Если среди них было переключение темы,
этот признак не теряется.

## Несколько мониторов

- У каждого дисплея свои сгенерированные обои, своя полоса и своё окно-наложение.
- При подключении или отключении монитора координаты экранов меняются: например, подключённый
  внешний монитор становится основным, и встроенный экран сдвигается вправо. Окна-наложения
  переставляются сразу при смене мониторов, при каждом `refresh` (в том числе когда обои ещё
  пересобираются) и при любом сдвиге окна системой (см. «OverlayWindow»).
- После отключения и подключения монитора система меняет его номер и может перепутать обои: отдать
  монитору сгенерированный файл другого дисплея или подставить свои стандартные обои. Приложение
  узнаёт монитор по UUID и ищет оригинал по записи (см. «Engine»), а не по номеру или имени файла.
  Сгенерированный файл на «не том» мониторе заменяется копией от его собственного оригинала.
- **Окно ожидания (10 с)** после подключения, отключения, пробуждения или возврата в сеанс: если за
  это время на мониторе с известной записью появились другие обычные обои, приложение считает их
  подстановкой системы и возвращает обои пользователя. Выбор обоев вручную позже, чем через 10 с
  после смены мониторов, принимается как обычно. Для проверки: `kill -USR1 <pid>` имитирует смену
  мониторов.
- Если в Системных настройках выбраны одни обои на все мониторы, первая установка обоев на один
  дисплей может применить их ко всем. После этого приложение пересобирает обои остальных дисплеев,
  и дальше у каждого монитора свои обои.

Проверено: отключение и повторное подключение внешнего монитора восстанавливает полоски на обоих
экранах.

## Энергопотребление

- **Нет опроса.** Единственное периодическое пробуждение — страховочный таймер раз в 60 с с допуском
  30 с. Пока мониторы погашены, он остановлен.
- **Тяжёлая работа только при изменениях** (новые обои, другой монитор, другая высота строки меню,
  смена темы для динамических обоев) и в фоновой очереди с низким приоритетом. После неё память
  возвращается системе (`malloc_zone_pressure_relief`).
- **Смена темы** не трогает обычные (одиночные) обои: они выглядят одинаково в светлой и тёмной
  теме. Пересобираются только динамические.
- **Один запрос списка окон** к WindowServer за обновление, общий для всех дисплеев.
- **Непрозрачные картинки** без альфа-канала: PNG меньше и быстрее кодируется, системе быстрее его
  загружать, дешевле наложение полосы.
- **Окно-наложение хранит только свою полосу**, а не полноэкранный битмап, из которого она вырезана:
  это десятки мегабайт на дисплей.
- **Без анимаций:** полоса меняется за один кадр, окно не анимируется, AppKit никогда не просит его
  перерисоваться.

Замер на двух мониторах в простое: 0 % CPU, 0 пробуждений в секунду, около 12 МБ памяти.

## Файлы и настройки на диске

| Где | Что |
|---|---|
| `~/Library/Application Support/HidenKO/wallpaper-<id>-<время>.png` | Сгенерированные обои, по одному файлу на монитор. Старые удаляются после установки новых; файл отключённого монитора остаётся; при возврате обоев удаляются все, на которые не ссылается ни одна запись. |
| `defaults read local.hidenko.app records.v2` | Запись на каждый монитор (ключ — UUID): исходные обои, масштабирование, сгенерированный файл. Нужна, чтобы вернуть обои после сбоя или смены номеров мониторов. Удаляется для мониторов, где обои вернулись. |
| `~/Library/Application Support/HidenKO/last-known.json` | Независимая копия «монитор → оригинал». Не удаляется при выходе, используется, если записи потеряны. |

Файлы из старой папки `~/Library/Application Support/ClearBar` (ранняя версия под названием ClearBar)
тоже считаются сгенерированными и никогда не принимаются за исходные обои.

## Отладка

Запустите бинарник напрямую с переменной `HIDENKO_DEBUG=1`, чтобы видеть в терминале пересборки
и изменения папки обоев:

```bash
HIDENKO_DEBUG=1 build/HidenKO.app/Contents/MacOS/HidenKO
```

Ошибки пишутся всегда через `NSLog` с префиксом `HidenKO:`, например:
- `display N shows a generated file and its original is unknown; leaving it alone` — исходные обои
  этого дисплея неизвестны, см. раздел ниже;
- `restore failed for display N` — система отказалась вернуть исходные обои;
- `CABackdropLayer not available` — закрытый класс пропал в новой macOS.

## Ограничения

- Динамические, аэро- и видеообои превращаются в статичный снимок текущего светлого или тёмного
  варианта. Снимок пересобирается при смене темы.
- Если строка меню скрывается автоматически, окно-наложение не показывается.
- После `kill -9` или сбоя приложение не успевает вернуть обои. При следующем запуске оно найдёт
  оригинал по сохранённому пути; если запускать не планируется, выберите обои вручную.
- Работа зависит от закрытого `CABackdropLayer`.

## Если что-то пошло не так

**Новые обои не применяются, строка меню остаётся обычной.** Если обои лежат в «Загрузках»,
«Документах» или на «Рабочем столе», macOS спрашивает HidenKO о доступе к этой папке, и до ответа
обработка стоит. Разрешите доступ в окне запроса или в Системных настройках → Конфиденциальность и
безопасность → Файлы и папки → HidenKO. Проверить, что приложение ждёт именно этого: процесс почти
не тратит CPU, а `sample <pid>` показывает поток `hidenko.worker` в вызове `open`.

**Чёрная полоса над строкой меню, а приложение её не убирает.** Скорее всего, на экране стоит
сгенерированный файл, а путь к исходным обоям потерян. Выберите обои заново в Системных настройках →
Обои (для каждого монитора), приложение подхватит их само.

**Проверить, какие обои сейчас стоят:**
```bash
plutil -p ~/Library/Application\ Support/com.apple.wallpaper/Store/Index.plist | grep relative
```
Путь вида `.../Application Support/HidenKO/wallpaper-...png` означает, что стоят сгенерированные обои.

**Работают две копии приложения.** Проверьте и оставьте одну:
```bash
pgrep -fl HidenKO
```

## История изменений

### Полоски не на своём месте (15 ноября 2026)
- Исправлено: окна-наложения оставались посреди экрана после пробуждения, смены мониторов или выбора
  новых обоев. Окно переставлялось только когда пересборка не требовалась, а показывалось через
  0,8 с после пересборки без проверки места. Теперь окно знает UUID своего монитора и само
  возвращается над его строкой меню при любом сдвиге; без своего монитора не показывается.
- `build.sh` подписывает сертификатом Apple Development: разрешение на доступ к «Загрузкам» больше
  не сбрасывается после каждой сборки, и обработка обоев не зависает на системном запросе.

### Переподключение монитора (ноябрь 2026)
- Исправлено: после отключения и подключения внешнего монитора слетали обои на внешнем или встроенном
  экране. Номер дисплея при этом меняется, и приложение теряло, какие обои чьи. Теперь монитор
  определяется по UUID, а оригинал ищется по записи на диске (`records.v2`).
- Подмена файлов между мониторами исправляется: на каждом мониторе ставится копия его собственных обоев.
- Окно ожидания 10 с после смены мониторов: стандартные обои, которые система сама поставила, не
  принимаются за выбор пользователя.
- Сигнал `USR1` имитирует смену мониторов (для проверки).
- Исправлено: после выключения и включения (или перезапуска) у обоих мониторов оставались ссылки на уже
  удалённые сгенерированные файлы, а записи об оригиналах были стёрты, и приложение писало «original
  is unknown». Причины: очистка удаляла файлы, на которые ещё ссылалось хранилище обоев macOS; возврат
  обоев не проверялся. Теперь такие файлы не удаляются, недостающие создаются заново, возврат
  проверяется, а оригиналы дублируются в `last-known.json`.

### Энергопотребление и несколько мониторов (октябрь 2026)
- Смена темы пересобирает только динамические обои.
- Один запрос списка окон на обновление вместо одного на каждый дисплей.
- Непрозрачные битмапы; полоса хранится в отдельном маленьком буфере; одна полноэкранная копия
  при обработке вместо двух.
- Обновление полосы без анимации, окно-наложение без анимации и без перерисовки.
- Исправлено: переключение темы терялось, если одновременно приходило другое событие.
- Исправлено: после подключения монитора окно-наложение оставалось на старых координатах, и на
  встроенном экране была видна чёрная полоса.
- Исправлено: новый монитор с унаследованными сгенерированными обоями оставался с чёрной полосой.
- Исправлено: выключение приложения могло стереть сохранённые пути к исходным обоям, пока на экране
  ещё стоял сгенерированный файл.
